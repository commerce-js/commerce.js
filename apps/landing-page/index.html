The Problem

Every platform is a walled garden

Different APIs, data shapes, auth flows, and price formats. Build on one, locked into one.

🔒

Platform Lock-In

Build on Salla? Everything is Salla-shaped. Switch to Medusa? Rewrite 100% of your integration layer. Start from zero.

🧩

Fragmented APIs

Salla uses OAuth. Medusa uses JWT. Salla prices in major units. Medusa in minor. No two platforms agree on anything.

💸

Linear Cost Growth

Agencies maintaining storefronts for clients on 3 different platforms need 3 separate codebases. Costs multiply.

The Solution

One interface. Every backend.

Commerce.js defines 26 canonical types and maps each backend to them through adapters.

1

Install the Nuxt 4 module

One package. Auto-registers 46 server routes, composables, and the event bus.

$ npx nuxi module add @commercejs/nuxt
2

Pick your adapter

Connect to your eCommerce backend in one line. Salla, Medusa, or bring your own.

commerce: { adapter: 'salla' } // or 'medusa', 'shopify', etc.
3

Build with unified composables

Your frontend codes against types — not APIs. Every composable works with every adapter.

const { products } = await useProducts() const { cart, addToCart } = await useCart() const { createOrder } = await useOrders()
4

Switch backends. Keep everything.

Change one config line. Zero rewrites. Your frontend, composables, providers, and tests stay the same.

Features

Everything you need. Nothing you don't.

⚡

Composable Adapters

Each adapter maps a backend's API to 26 unified TypeScript types. Products, carts, orders, customers — all normalized. Works with any backend that speaks HTTP.

🔌

Pluggable Providers

Payments (Tap), email (Resend), analytics (GA), delivery (Armada, Parcel) — all swappable. Register once, use across every adapter.

🛡️

Platform Fallback Engine

If an adapter doesn't support wishlists, reviews, or carts? The platform engine fills the gap with SQLite or Postgres — automatically.

📡

Event-Driven Architecture

Every commerce action emits events. Hook into order:created, cart:updated, or payment:completed to add custom logic without touching core code.

🔐

Auto-Generated API

46 server routes with OpenAPI spec, Scalar UI, and type-safe request/response. Zero boilerplate — the Nuxt 4 module handles everything.

🌙

MENA-Native

First-class Salla adapter, Tap Payments, Armada & Parcel delivery, RTL-ready UI, SAR currency — built in, not bolted on.
