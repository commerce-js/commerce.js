# T03: `apps/storefront` — Fly.io migration

---

**Status**: 🟡 **Planned**
**Effort**: Small
**Blocked By**: T01 (needs a live `/api/storefront/*` endpoint to point at)

## Goal

Migrate `apps/storefront` from the `cloudflare-pages` Nitro preset to `node-server`, wire it
to the hosted API via `remoteApiBase`, and verify a clean production build so it's ready to be
added as a second Fly.io process in T04.

## Context

`apps/storefront` was built for the Cloudflare Pages era. It uses `preset: 'cloudflare-pages'`
in `nuxt.config.ts` and has a `wrangler.toml`. On the `fly/eaas` branch, everything runs on
standard Node.js. The storefront needs the same treatment the dashboard got in Step 1.

After this task, the storefront can be pointed at the live `commercejs-cloud` API
(`acme.commercejs.cloud/api/storefront`) in remote mode. In T04, it gets embedded as a second
process in the same Fly app.

## Requirements

### 1. Nitro preset swap

```ts
// apps/storefront/nuxt.config.ts
nitro: {
  preset: 'node-server',   // was 'cloudflare-pages'
}
```

Remove `wrangler.toml` from `apps/storefront/`.

### 2. Switch to remote API mode

Point the storefront at the live API using T02's `remoteApiBase` config:

```ts
// nuxt.config.ts
commerce: {
  apiRoutes: false,
  apiBase: '/api/storefront',
  // remoteApiBase set via env: NUXT_COMMERCE_REMOTE_API_BASE
},
```

At build time and in Fly secrets, set:
```
NUXT_COMMERCE_REMOTE_API_BASE=https://acme.commercejs.cloud/api/storefront
NUXT_COMMERCE_API_KEY=cjs_live_xxx   # merchant's API key
```

For the hosted EaaS case (T04), `REMOTE_API_BASE` will not be needed — the storefront
process will call the API process on localhost. This env var is only for standalone / self-hosted.

### 3. Merchant config injection

The storefront needs to know the merchant's store name, currency, locale, and theme at
server-start time. Add a Nitro server plugin that loads store config on startup:

```ts
// apps/storefront/server/plugins/merchant-config.ts
export default defineNitroPlugin(async () => {
  // On process start, fetch store info from the API
  // Cache in memory — refreshed on restart
  // Exposed via useRuntimeConfig().public.store
})
```

This populates `<title>`, OG tags, currency formatter, and RTL flag without a per-request DB hit.

### 4. RTL / locale support

The storefront's `app.config.ts` and `nuxt.config.ts` should read `locale` from the injected
merchant config. Arabic (`ar-SA`) → add `dir="rtl"` to `<html>`. Already has the Tailwind RTL
setup; just needs the locale wiring.

### 5. Remove Cloudflare dependencies

- Delete `apps/storefront/wrangler.toml`
- Remove `@cloudflare/workers-types` from devDependencies if present
- Remove `cloudflare-pages` from `nitro.preset` (step 1)

### 6. Build verification

`pnpm --filter @commercejs/storefront build` must succeed and emit `.output/server/index.mjs`.
