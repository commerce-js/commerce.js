# T05: Dashboard Deploy Integration

---

**Status**: 🟡 **Planned**
**Effort**: Medium
**Blocked By**: T04 (project persistence must exist first)

## Goal

Wire the dashboard UI to trigger deployments — a "Deploy" button on the project page that calls `DeployOrchestrator` server-side and shows real-time deployment status.

## Context

T01-T03 validated the deploy pipeline through the CLI. T04 added project persistence to the dashboard. T05 closes the loop — the dashboard becomes a visual interface for the same proven deployment orchestration.

## Requirements

### 1. Deploy Server Route

`POST /api/projects/:id/deploy`:
- Reads the project from D1 (project name, repo URL, env vars)
- Creates a `DeployOrchestrator` with Cloud credentials from runtime config
- Calls `orchestrator.deploy()` with project config
- Stores the deployment record in the `deployments` table
- Returns the deployment result

### 2. Dashboard UI Updates

- Project detail page (`/projects/[id]`): Add "Deploy" button
- Deployment list: Show deployment history with status badges
- Latest deployment: Show URL, status, build time
- Error display: Show build errors when deployment fails

### 3. Real-Time Deploy Status (stretch goal)

- Use SSE or polling to update deployment status in the UI
- Show: building → deploying → ready (or failed)
- Display build log output
