# T03: CLI Deploy End-to-End

---

**Status**: 🟡 **Planned**
**Effort**: Medium
**Blocked By**: T02 (build pipeline must work first)

## Goal

Make `commercejs deploy` work end-to-end — deploy `apps/storefront` to Cloudflare Pages with a Neon Postgres database and verify the store is live.

## Context

This is the milestone task — the first real deployment from the CLI. T01 validated the providers, T02 added the build pipeline. T03 wires them together through the CLI and validates the full flow with a real store.

## Requirements

### 1. CLI Configuration

`loadCloudConfig()` in `packages/cli/src/utils/config.ts` needs to:
- Read Cloudflare + Neon credentials from env vars or `.commercejs.json`
- Support a `--project-dir` flag (defaults to cwd)
- Resolve project ID from config or generate from directory name

### 2. End-to-End Flow

```bash
# From the storefront directory:
cd apps/storefront
commercejs deploy --env production

# What happens:
# 1. Reads CF_API_TOKEN, CF_ACCOUNT_ID, NEON_API_KEY from env
# 2. Provisions: Neon DB + KV + R2 (if first deploy)
# 3. Sets DATABASE_URL on Cloudflare Pages project
# 4. Runs: pnpm install → pnpm db:migrate → nuxt build
# 5. Runs: wrangler pages deploy .output/public --project-name=cjs-storefront
# 6. Outputs: "✅ Deployed to https://cjs-storefront.pages.dev"
# 7. Health check: GET the URL, expect 200
```

### 3. Idempotent Deploys

Subsequent deploys should:
- Skip infrastructure provisioning (Pages project already exists)
- Run migrations (may be no-ops)
- Build and deploy fresh
- Use the same project name and DB

**Implementation**: Store deploy state in `.commercejs.json` (project ID, Neon project ID, etc.) after first deploy.
