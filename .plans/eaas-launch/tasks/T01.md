## Goal

Clear the six-item technical-debt backlog that accumulated across
T01–T13. None of these are blocking, but all are small, all have been
sitting in `.memory/checkpoint.md` carry-over lists for weeks, and the
USelect-sentinel helper in particular is wanted on day one of T03's
admin UX work. Ship as a single focused commit bundle; no new features.

## Context

Six distinct cleanup items:

1. **USelect sentinel helper** — four consumers deep (T08 '__root__',
   T13 'all', T12-fix '__default__', T03 status 'all'). Each re-implements
   a sentinel-to-real-value mapping in its own v-model computed.
2. **bcrypt async compare** — `packages/platform/src/admin/auth.ts`
   uses `compareSync` which blocks the Node event loop ~100 ms per
   login. Trivial 5-line swap. Flagged in the T01 post-review.
3. **Categories hardening** — three gaps surfaced during T08:
   - `deleteCategory` only blocks when children exist; categories
     with attached products delete silently, orphaning product↔category
     links.
   - `updateCategory` accepts any `parentId` — no check against
     self-parent or descendant cycles, so the tree can be broken by
     pointing A at A (or at a descendant of A).
   - `Category` type omits `sortOrder`, so `mapCategory` can't return
     it. T08's form keeps `sortOrder` as a write-only field as a
     consequence.
4. **T13 "deleted" chip UX polish** — the badge only fires when
   `actorId === null` (system actions). Deleted admins leave an orphan
   actorId on past rows; the snapshot `actorEmail` still renders, but
   the UI gives no signal that the admin is gone. Cross-check against
   live `listAdmins()` to tag orphans with a muted "(deleted)" chip.
5. **Smoke merchant schema drift** — `products.id=UUID` vs
   `order_items.product_id=TEXT` on the smoke merchant's Neon branch,
   currently absorbed via `::text` casts in the analytics raw-SQL
   queries (fixed inline during T11 acceptance). Any new raw SQL join
   across these columns needs the same guard until normalized. Option
   here is to pg-dump + drop-and-recreate the smoke branch on current
   schema, retiring the casts.
6. **`@commercejs/storage-s3 v0.2.1` unreleased changeset** — T04
   attached a changeset for the presign signature fix (X-Amz-Expires
   was being set post-sign). Unreleased. One command: `pnpm release`.

## Requirements

### 1. USelect sentinel helper

New file: `apps/storefront/app/composables/useSelectSentinel.ts`.

```ts
/**
 * Bridges Reka SelectItem's empty-string ban to real values (including '').
 * Returns a v-model that maps a sentinel string to the underlying value.
 *
 * @example
 *   const status = ref<'' | 'draft' | 'active' | 'archived'>('')
 *   const model = useSelectSentinel(status, { sentinel: 'all', empty: '' })
 *   // model.value === 'all' when status === ''
 *   // setting model.value to 'all' writes '' to status
 */
export function useSelectSentinel<T>(
  source: Ref<T>,
  opts: { sentinel: string; empty: T }
): WritableComputedRef<string | T> { /* ... */ }
```

Convert all four existing consumers to use it:

- `/admin/products/index.vue` — status filter
- `/admin/categories/new.vue` + `/admin/categories/[id]/edit.vue` — parent
  dropdown (`'__root__'`)
- `/admin/theme.vue` — font dropdown (`'__default__'`)
- `/admin/activity.vue` — actor + entityType dropdowns (`'all'`)

### 2. bcrypt async compare

`packages/platform/src/admin/auth.ts`:

```diff
- import bcrypt from 'bcryptjs'
  ...
- const ok = bcrypt.compareSync(password, row.passwordHash)
+ const ok = await bcrypt.compare(password, row.passwordHash)
```

Verify the `hashSync` vs async `hash` balance — createAdmin may also
be sync. Switch both.

### 3. Categories hardening

Three fixes in `packages/platform/src/admin/categories.ts` +
`packages/types/src/category.ts`:

- `deleteCategory`: add a products-attached check. If
  `findProductIdsByCategory(id).length > 0` → throw with a message that
  the dashboard `[id].delete.ts` route can surface as 400.
- `updateCategory`: if `input.parentId` is provided, walk the parent
  chain; reject if `input.parentId === id` or if the chain ever
  reaches `id` (descendant cycle).
- `Category` type: add `sortOrder: number`. Update `mapCategory` in
  `packages/platform/src/domains/categories.ts` to return it. T08's
  form can drop the "write-only" workaround; T08's list page can add
  the sort column back.

Add unit tests next to `admin-orders-guards.test.ts`:
- deleteCategory with products attached → rejects
- updateCategory cycle rejection (self + descendant)
- mapCategory returns sortOrder

Query parity stays green (no new queries; these all reuse existing
finds).

### 4. T13 deleted-chip polish

`apps/storefront/app/pages/admin/activity.vue`:

- Fetch `/api/admin/staff` once (already done for actor dropdown) —
  build a Set of live admin ids.
- In the timeline row, render the "deleted" chip when
  `ev.actorId && !liveAdminIds.has(ev.actorId)`, not just on
  `!ev.actorId`.
- Keep the current chip for system actions (null actorId).

No platform/API changes.

### 5. Smoke merchant schema normalize (OPTIONAL)

Two options here — pick in the commit:

- **Option A**: pg_dump the smoke merchant's Neon branch, drop the
  branch, recreate via the worker's `provision-store` job, restore
  the dump after normalizing UUID columns. One-time pain, retires
  the `::text` casts.
- **Option B**: leave the drift + casts in place, document the
  pattern in `.memory/gotchas.md` so future analytics queries reach
  for it automatically.

If the dump/restore is non-trivial, go with Option B and save the
migration work for a dedicated `.plans/schema-normalize/` plan.

## Implementation Notes

- **Bundle or split?** Single commit for items 1+2+3+4+6, optional
  second commit for item 5 if Option A is chosen. Do NOT split into
  six PRs — these are all small enough to review together, and
  splitting would blow up into six deploy cycles.
- **Helper naming**: `useSelectSentinel` is deliberately verbose.
  `useSelect` would collide with Nuxt UI's component naming.
- **bcrypt swap order**: swap `compareSync` first, land, verify login
  still works, then swap `hashSync`. Two cheap tests beats one
  expensive rollback.
- **Categories hardening**: if any of the three guards break T08's
  existing UI flow, flag + narrow scope rather than rewriting T08.
  The UI can stay on its current workarounds if the platform guards
  trigger unexpected errors.
