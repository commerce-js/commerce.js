# T02: Build Pipeline in DeployOrchestrator

---

**Status**: 🟡 **Planned**
**Effort**: Large
**Blocked By**: T01 (providers must be validated first)

## Goal

Implement the missing build pipeline in `DeployOrchestrator` so it can take a project directory, build a Nuxt storefront, run database migrations, and upload the output to Cloudflare Pages.

## Context

The current `DeployOrchestrator.deploy()` provisions infrastructure (Pages project, R2, KV, Neon DB) but then calls `deployPages(projectName, './output')` assuming a pre-built output directory exists. The entire build step is missing — there's no clone, install, migrate, or build logic. This is the core gap preventing real deployments.

## Requirements

### 1. Build Pipeline Steps

The orchestrator's `deploy()` should run this pipeline:

```
1. Resolve project directory (local path or git clone URL)
2. Install dependencies (pnpm install)
3. Set environment variables (DATABASE_URL, etc.)
4. Run database migrations (pnpm --filter @commercejs/platform db:migrate)
5. Build the Nuxt app (nuxt build / pnpm run build)
6. Upload output directory to Cloudflare Pages (direct upload)
7. Set env vars on the Cloudflare Pages project
8. Health check (fetch the deployed URL)
```

**Key Considerations**:
- The pipeline runs in Node.js (CLI context) — use `execa` for shell commands
- For initial version, support local directory deploy (not git clone)
- Git clone can be added in a later iteration (GitHub integration)
- The Cloudflare Pages Direct Upload API requires multipart form data with the build output

### 2. Cloudflare Pages Direct Upload

The current `deployPages()` method sends a simple POST. Real Pages Direct Upload requires:
- Reading all files from the output directory
- Computing file hashes
- Uploading file manifest, then individual file contents
- Or using `wrangler pages deploy` as a simpler alternative

**Decision needed**: Direct API upload vs. `wrangler pages deploy` subprocess.
Recommendation: Use `wrangler pages deploy ./output --project-name=<name>` initially — simpler, well-tested, avoids reimplementing the upload protocol.

### 3. Environment Variable Injection

Deployed stores need these env vars set on Cloudflare Pages:
- `DATABASE_URL` — Neon connection string (from provisioning step)
- `NUXT_COMMERCE_*` — Commerce.js config
- Any project-specific env vars

**Implementation**: Use Cloudflare API `PATCH /projects/:name` to set env vars, or pass them during build.
