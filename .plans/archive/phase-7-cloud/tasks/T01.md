# T01: Validate Cloud Providers

---

**Status**: 🟡 **Planned**
**Effort**: Medium
**Blocked By**: Cloudflare API token + Neon API key in env

## Goal

Validate `CloudflareProvider` and `NeonProvider` against real APIs — create a Pages project, R2 bucket, KV namespace, and Neon database branch, then tear them down.

## Context

The Cloud providers are well-typed `ofetch` wrappers but have never been tested against real APIs. Before building the deploy pipeline on top of them (T02), we need confidence that the API calls actually work — correct endpoints, auth, request/response shapes.

## Requirements

### 1. Integration Tests for CloudflareProvider

Write tests gated behind `CF_API_TOKEN` + `CF_ACCOUNT_ID` env vars. Tests should:
- Create a Pages project → verify it exists → delete it
- Create an R2 bucket → verify → delete
- Create a KV namespace → verify → delete

**Key Considerations**:
- Tests must clean up after themselves (delete created resources)
- Skip tests gracefully when env vars are missing (`describe.skipIf`)
- Use unique names with timestamps to avoid collisions

### 2. Integration Tests for NeonProvider

Write tests gated behind `NEON_API_KEY` env var. Tests should:
- Create a Neon project → verify → delete it
- Create a branch from main → verify → delete
- Get connection string for a branch

**Key Considerations**:
- Neon project creation takes a few seconds — may need longer timeouts
- Use `afterAll` to ensure cleanup even on test failure

### 3. Fix Any API Issues Found

If real API responses differ from expected shapes, fix the provider code. Document findings in `.memory/gotchas.md` if there are surprises.
