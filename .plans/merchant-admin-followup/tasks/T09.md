# T09: Staff management (local-password)

---

**Status**: 🟡 **Planned**
**Effort**: Small/Medium
**Blocked By**: None. The email-invite flow is out of scope (owned by the transactional-email workstream).

## Goal

The merchant account owner can add + remove + change-role their store's
staff from `/admin/staff`. Every new staff user gets a local-password
account (owner enters a password, shares it out-of-band). Role picker
(owner / admin / editor). The last owner cannot be removed.

## Context

Platform exposes:

- `admin.auth.createAdmin({ email, password, name?, role? })`
- `admin.auth.listAdmins()`
- `admin.auth.getAdmin(id)`
- `admin.auth.deleteAdmin(id)`
- `admin.auth.changePassword(adminId, currentPassword, newPassword)`
- `admin.auth.seedInitialAdmin()` (used by the tenant middleware on
  first-ever login — already wired)

T09 wraps those into HTTP + UI. One small schema change: add a `status`
enum field to `admin_users` so T11-style invite flow (in the
email-workstream plan) doesn't need a retroactive migration.

## Requirements

### 1. Schema prep (merchant branch DB)

Add to `packages/platform/src/database/prisma/schema/admin-user.prisma`
(or the equivalent): `status String @default("active")`. Drizzle sibling
adds the same column. Values: `'active' | 'invited' | 'disabled'`. T09
only uses `'active'`; `'invited'` is reserved for the future email flow;
`'disabled'` is available if a future task adds a "deactivate" action
without full delete.

Ship one migration. Verify `migratePrisma()` in the tenant middleware
runs it on next request against `smoke.commercejs.cloud`.

### 2. AdminAPI extension

Extend `listAdmins()` + `getAdmin()` return to include `status` (via
`AdminUserSafe`). `createAdmin()` implicitly sets `status = 'active'`.
Add `admin.auth.updateAdmin(id, { name?, role? })` if not already present
(needed for T09's edit page).

### 3. API routes under `apps/dashboard/server/api/admin/staff`

- `index.get.ts` — `admin.auth.listAdmins()`.
- `index.post.ts` — body `{email, password, name?, role?}` → `admin.auth.createAdmin`.
- `[id].get.ts` — `admin.auth.getAdmin`.
- `[id].patch.ts` — body `{name?, role?}` → `admin.auth.updateAdmin`.
- `[id].delete.ts` — `admin.auth.deleteAdmin` with server-side
  "prevent deleting last owner" guard.

All gated by `requireMerchantSession`. Write routes additionally check
that the session actor's role is `'owner'` (only owners can manage staff).

### 4. Zod schemas

`createStaffSchema` (email, password ≥8 chars, name?, role enum),
`updateStaffSchema` (partial — name?, role?).

### 5. Pages

- `/admin/staff/index.vue` — table: email, name, role badge, status badge,
  actions (Edit / Remove). "Add staff" CTA.
- `/admin/staff/new.vue` — form: email, password (show/hide toggle),
  name, role. On save, show the password once in a "share with the new
  user" banner (don't rely on email). Toast + redirect to list.
- `/admin/staff/[id]/edit.vue` — form: name, role. Prevent changing own
  role. Separate "Change password" button → modal with current + new
  password.

### 6. "Last owner" guard (server-side)

In `[id].delete.ts` AND `[id].patch.ts` (role change), count
`listAdmins().filter(a => a.role === 'owner')`. If current count is 1 and
the target is the last owner, return 400 "Cannot remove the last owner".

Duplicate the check on the platform side if not already present, so CLI
scripts can't bypass. Verify during testing.

### 7. Sidebar link

Add "Staff" to `apps/storefront/app/layouts/admin.vue` between
Categories and Settings (or wherever fits the information architecture).

## Implementation Notes

- **No email send**. T09's create flow shows the password once in the UI
  and leaves "communicate to the user" as the owner's responsibility.
  The follow-up email-workstream plan picks this up and replaces the
  inline-password flow with a "send invite" path that sets
  `status='invited'` and emails a token.
- **Status enum is tri-state prep**, not user-facing in v1. The UI
  renders a muted `'active'` chip on every staff row; `'invited'` +
  `'disabled'` will render in the email-workstream plan.
- **Owner self-role-change**: prevent the UI from editing the session
  actor's own role (would lock them out if they demote themselves). The
  server-side "last owner" guard covers the worst case.
- **bcrypt.compareSync gotcha** — see `.memory/checkpoint.md`, carried
  over from T01 review. Not a T09 blocker but worth noting as adjacent.
