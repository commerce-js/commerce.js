# T11: Analytics expansion

---

**Status**: ✅ **Completed** (2026-04-20)
**Effort**: Large
**Blocked By**: None.

## Goal

A logged-in merchant can see meaningful commerce analytics beyond the
basic counts on the `/admin` index: revenue over time (day / week /
month), top-selling products, top customers by spend, average order
value (AOV), and refund rate. All filterable by date range.

Conversion rate is explicitly out of scope (requires session tracking —
not part of CommerceJS today).

## Context

The platform currently ships `admin.getDashboardStats()` which returns
surface-level counts + `recentOrders` + `ordersByStatus`. The `/admin`
index page (T02) renders this. T11 adds the analytics-deep views as a
new sibling page (`/admin/analytics`) driven by new platform queries.

This is the first task in the plan that introduces **new platform
queries on both Prisma and Drizzle drivers**. The repo's parity rule
applies: every new query has a Prisma implementation AND a Drizzle
implementation, and `packages/platform/scripts/check-query-parity.sh`
must stay green. Unit tests mirror
`packages/platform/src/__tests__/admin-orders-guards.test.ts`.

## Requirements

### 1. Platform: new `AdminAPI` methods

Append to `packages/platform/src/admin/types.ts`:

```ts
interface AdminAPI {
  // ... existing ...

  getRevenueTimeSeries(params: {
    granularity: 'day' | 'week' | 'month'
    from: string   // ISO date or datetime
    to: string
  }): Promise<Array<{ bucket: string; revenue: number; orderCount: number }>>

  getTopProducts(params: {
    limit?: number
    from?: string
    to?: string
  }): Promise<Array<{ productId: string; name: LocalizedString; sku: string | null; unitsSold: number; revenue: number }>>

  getTopCustomers(params: {
    limit?: number
    from?: string
    to?: string
  }): Promise<Array<{ customerId: string; email: string; orderCount: number; lifetimeValue: number }>>
}
```

Extend `DashboardStats` in the same file to include:

```ts
  avgOrderValue: number
  refundRate: number       // refunded / total orders, excluding cancelled
```

Both fields populate in `admin.getDashboardStats()` — the existing
`/admin` index picks them up automatically.

### 2. Platform: new queries

For each of the four methods above, write matching queries in:

- `packages/platform/src/database/prisma/queries/admin-analytics.ts` (new)
- `packages/platform/src/database/drizzle/queries/admin-analytics.ts` (new)
- Export both through the barrel, keeping
  `check-query-parity.sh` green.

Use the existing `parseFromBound` / `parseToBound` helpers from
`packages/platform/src/database/date-bounds.ts` so date-only inputs work
across both drivers.

### 3. Platform: domain wiring

- `packages/platform/src/admin/analytics.ts` (new) — `createAdminAnalyticsDomain()` that exposes the four methods above.
- Plug into `createAdminAPI()` in `packages/platform/src/admin/index.ts`.

### 4. Platform: unit tests

At `packages/platform/src/__tests__/admin-analytics.test.ts`:

- `getRevenueTimeSeries` returns bucketed revenue with zero-filled gaps.
- `getTopProducts` respects `limit` and excludes refunded orders from
  revenue.
- `getTopCustomers` orders by lifetimeValue descending, respects limit.
- AOV = totalRevenue / orderCount.
- refundRate ∈ [0, 1].

Mock the query layer the same way `admin-orders-guards.test.ts` does.

### 5. API routes under `apps/dashboard/server/api/admin/analytics`

- `revenue.get.ts` — `?granularity=&from=&to=` → `admin.getRevenueTimeSeries`.
- `top-products.get.ts` — `?limit=&from=&to=` → `admin.getTopProducts`.
- `top-customers.get.ts` — `?limit=&from=&to=` → `admin.getTopCustomers`.

All gated by `requireMerchantSession`. Zod schemas in `admin-schemas.ts`.

### 6. Page (`/admin/analytics.vue`)

Sections:

- **Date range** — dropdown (last 7 days / last 30 days / last 90 days /
  custom). Custom opens two date inputs.
- **KPI tiles** — AOV, refund rate, order count, revenue (all in store
  currency via `usePrice`).
- **Revenue chart** — bar or line chart. Use Nuxt UI's `UChart` if
  available on v4, otherwise a small wrapper around Chart.js via
  `@nuxtjs/chart.js` or similar (pick during implementation; prefer zero
  extra deps if `UChart` fits).
- **Top products table** — top 10 by revenue, with thumbnail + units sold
  + revenue. Click → `/admin/products/:id/edit`.
- **Top customers table** — top 10 by lifetime value. Click →
  `/admin/customers/:id`.
- **Conversion rate placeholder** — muted tile reading "Conversion rate
  — not yet tracked (requires session tracking, coming soon)". Prevents
  the "where's conversion rate?" ticket.

### 7. Dashboard index update

Add the AOV + refund rate tiles to the existing `/admin/index.vue` top

## Implementation Notes

- **Refund-rate denominator**: refunded / (total − cancelled). Cancelled
  orders never paid, so including them inflates the rate artificially.
- **Time-series zero-fill**: if the date range covers 7 days but only 3
  had orders, return 7 buckets (zero-revenue for the 4 quiet days) so
  the chart renders without gaps.
- **Top-N ties**: tie-break alphabetically (by product name / customer
  email) so pagination is deterministic if we ever add it.
- **Scope creep signal**: if merchants ask for "sales by category" or
  "sales by channel" — stop and open a v2 plan. Don't inflate T11.
- **Chart library**: prefer `UChart` if it exists on the Nuxt UI v4
  surface. If not, evaluate `chart.js` + `vue-chartjs` (smallest
  footprint, well-supported). Avoid full-fat D3 — overkill for 4 charts.

  TEXT).

**Challenges encountered**:
- **Schema drift across merchant Neon branches** — the smoke merchant DB
  (provisioned earlier in the fly/eaas migration) has `products.id`
  typed as `uuid` while `order_items.product_id` is `text`.
  Later-provisioned branches may be consistent, but the analytics
  `$queryRaw` joins crash with PG 42883 on drifted branches. Fixed
  by wrapping every join key with `::text` casts on both Prisma and
  Drizzle sides — resilient to either schema shape. Same pattern may
  need to be applied to any future raw-SQL queries that join on
  product/customer/order IDs. Surfacing as a platform-hardening
  follow-up candidate.
- **Chart library decision** — Nuxt UI v4 has no `UChart` component,
  and pulling chart.js + vue-chartjs for a single bar chart would
  weigh the bundle down. Landed on an inline SVG chart with `<title>`
  tooltips (~40 lines of Vue). If a second chart (e.g. orders vs.
  refunds stacked) gets added, revisit with chart.js. Documented in
  the commit message.
- **Fly logs latency** — debugging the `uuid = text` error took three
  round-trips because `fly logs` was returning cached historical
  output. The fix was to `tee` a live tail while firing the request
  in parallel; the actual error only appeared on the second capture.
