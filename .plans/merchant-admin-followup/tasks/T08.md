# T08: Categories CRUD UI

---

**Status**: ✅ **Completed** (2026-04-19)
**Effort**: Small
**Blocked By**: None — all four `admin.*Category` methods exist; `GET /api/admin/categories` shipped in T03.

## Goal

A logged-in merchant can create / edit / delete categories from the admin
UI, with parent/child nesting. The product form (T03) already uses
categories as a multi-select; T08 adds the management surface that
populates that select.

## Context

Platform exposes:

- `admin.listCategories(parentId?): Promise<Category[]>`
- `admin.createCategory(input: CreateCategoryInput): Promise<Category>`
- `admin.updateCategory(id, input: UpdateCategoryInput): Promise<Category>`
- `admin.deleteCategory(id): Promise<void>` — platform enforces orphan
  prevention (can't delete a category with children or attached products).

`/api/admin/categories` (GET) already exists from T03 — for the product
form's parent-picker dropdown. T08 adds POST / PATCH / DELETE + the three
pages.

## Requirements

### 1. API routes under `apps/dashboard/server/api/admin/categories`

Current state: `apps/dashboard/server/api/admin/categories.get.ts` is a
flat file. Restructure into a directory:

- `categories/index.get.ts` — keep existing `admin.listCategories(parentId?)`.
- `categories/index.post.ts` — `admin.createCategory(body)`.
- `categories/[id].get.ts` — `admin.getCategory(id)` (add this method on
  AdminAPI if missing — listCategories already returns full objects, so a
  one-line wrapper suffices).
- `categories/[id].patch.ts` — `admin.updateCategory(id, body)`.
- `categories/[id].delete.ts` — `admin.deleteCategory(id)`.

All gated by `requireMerchantSession`.

### 2. Zod schemas in `admin-schemas.ts`

`createCategorySchema` / `updateCategorySchema` mirror `CreateCategoryInput`
(name, nameAr, slug, description, descriptionAr, image, parentId, sortOrder).

### 3. List page (`/admin/categories/index.vue`)

Flat table v1 (tree view is v2). Columns: name (EN + AR muted subtext),
slug, parent name, product count (from `Category.productCount` if set;
fallback "—"), sortOrder, actions (Edit / Delete).

"New category" CTA in header → `/admin/categories/new`.

### 4. New page (`/admin/categories/new.vue`)

Form fields: name, nameAr, slug (auto-generated from name if empty),
description, descriptionAr, image (reuse T04 presigned upload, context
`'category'`), parent (dropdown of existing categories, "—" = root),
sortOrder. Save → create → redirect to list.

### 5. Edit page (`/admin/categories/[id]/edit.vue`)

Same form pre-filled. Save → PATCH → toast + stay on page.

### 6. Delete handling

Delete button in the list row (with confirm modal). If the platform
returns 400 "has children" or "has products", surface that message as a
toast + refresh the list to confirm the row still exists.

### 7. Sidebar link

Add "Categories" to `apps/storefront/app/layouts/admin.vue` (it was never
there — add now between Products and Orders).

## Implementation Notes

- **Slug collision**: The platform generates unique slugs on create if
  none is provided (check `packages/platform/src/admin/categories.ts`).
  The form should pass `slug: undefined` when empty rather than an empty
  string to trigger that path.
- **Parent loop protection**: The platform must reject setting a
  category's parent to itself or any descendant. Verify during testing;
  if the platform doesn't enforce, flag as a separate follow-up rather
  than fixing in T08.
- **Tree view** (hierarchical rendering) is v2 — the flat list with
  parent-name column is enough for v1 given typical merchant category
  counts (<50).

**What was implemented**:

  `packages/platform/src/admin/categories.ts` (wraps existing

  name, nameAr, slug (optional), description, descriptionAr, parent

  string crash; `excludeId` prop keeps a category out of its own parent
  options on edit), sortOrder, image via T04 presign flow
  (`context: 'category'`, click-to-upload + replace/remove, 10 MB cap).
  `class="w-full"` on all inputs per the Nuxt UI default-inline-flex
  gotcha from last session.
- Three pages: `app/pages/admin/categories/{index,new,[id]/edit}.vue`
  mirroring the T03 products shape (flat `UTable`, "New category" CTA,
  confirm-modal delete, stay-on-page after PATCH).
- Sidebar `app/layouts/admin.vue` restores/inserts a "Categories" link
  with the tag icon between Products and Orders.
- T03 product form's parent dropdown regression: `/api/admin/categories`
  URL is unchanged by the directory restructure (Nitro maps both
  `categories.get.ts` and `categories/index.get.ts` to the same route),
