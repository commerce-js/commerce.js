# T06: Store Settings

---

**Status**: ✅ **Completed** (2026-04-19)
**Effort**: Small
**Blocked By**: None — `admin.getStoreSettings()` / `updateStoreSettings()` already exist on `AdminAPI`.

## Goal

A logged-in merchant can edit their own store settings — display name (EN/AR),
description, logo URL, favicon, currency, locale, timezone, contact email &
phone, physical address, and social links — from `/admin/settings`. Changes
persist to the merchant's Neon branch and are immediately reflected in the
storefront header + footer (via `useStoreInfo` on `apps/storefront`).

## Context

The platform already exposes everything needed:

- `admin.getStoreSettings(): Promise<StoreSettings>` returning a rich
  payload (name, nameAr, description, descriptionAr, logo, favicon,
  currency, locale, timezone, supportedCurrencies, supportedLocales,
  contactEmail, contactPhone, address, socialLinks).
- `admin.updateStoreSettings(input: UpdateStoreInput): Promise<StoreSettings>`
  accepting a partial payload.

T06 is purely HTTP wrappers + one Vue page. Same shape as T05's read/write
routes. No platform change required.

## Requirements

### 1. API routes under `apps/dashboard/server/api/admin/settings`

- `settings.get.ts` — `admin.getStoreSettings()`.
- `settings.patch.ts` — body parsed with `updateStoreSettingsSchema` →
  `admin.updateStoreSettings(body)`.

Both gated by `requireMerchantSession`.

### 2. Zod schema in `admin-schemas.ts`

`updateStoreSettingsSchema` mirrors `UpdateStoreInput`:

```ts
export const updateStoreSettingsSchema = z.object({
  name: z.string().min(1).optional(),
  nameAr: z.string().optional(),
  description: z.string().optional(),
  descriptionAr: z.string().optional(),
  logo: z.string().url().optional().or(z.literal('')),
  favicon: z.string().url().optional().or(z.literal('')),
  currency: z.string().length(3).optional(),
  locale: z.string().optional(),
  timezone: z.string().optional(),
  contactEmail: z.string().email().optional().or(z.literal('')),
  contactPhone: z.string().optional(),
  address: z.string().optional(),
  socialLinks: z.string().optional(), // JSON string of key-value map
})
```

Follow the `parseOrThrow` pattern.

### 3. Settings page (`/admin/settings.vue`)

Tabbed or single-column form. Groups:

- **Brand** — name, nameAr, description, descriptionAr, logo, favicon (logo + favicon can reuse T04's presigned upload flow)
- **Locale** — currency dropdown (from `supportedCurrencies`), locale dropdown (from `supportedLocales`), timezone text
- **Contact** — email, phone, address (textarea)
- **Social** — repeating key/value rows (facebook, instagram, tiktok, x, whatsapp…) serialized as a JSON string

Save button persists via `PATCH /api/admin/settings`. Success toast. Error toast surfaces the Zod message.

(removed in `0804c3b`).

## Implementation Notes

- `socialLinks` comes back from the platform as a `Record<string, string>`
  but the `UpdateStoreInput` sends it as a serialized JSON string — mirror
  that asymmetry in the form (stringify on save, parse on load).
- Currency / locale changes don't retroactively convert product prices.
  Document that caveat in the page help text (or as a small warning
  modal) so merchants aren't surprised.
- Logo/favicon upload reuses `/api/admin/uploads/presign.post.ts` with
  `context: 'store'`, yielding `merchants/${id}/store/${uuid}/${filename}`.

## Execution Summary

**Completed**: 2026-04-19

**What was implemented**:

- `updateStoreSettingsSchema` added to
  `apps/dashboard/server/utils/admin-schemas.ts`. Mirrors
  `UpdateStoreInput` field-for-field: `name.min(1).optional()`,
  `nameAr/description/descriptionAr/contactPhone/address.optional()`,
  `logo/favicon.url().optional().or(literal(''))` so the UI can clear
  either with an empty string, `currency.length(3)` for ISO codes,
  `contactEmail.email().optional().or(literal(''))`, `socialLinks` as a
  plain string (JSON payload wire-shape).
- `apps/dashboard/server/api/admin/settings.get.ts` — thin
  `requireMerchantSession` → `admin.getStoreSettings()` wrapper.
- `apps/dashboard/server/api/admin/settings.patch.ts` — same gate +
  `parseOrThrow(updateStoreSettingsSchema)` → `admin.updateStoreSettings()`.
- `apps/storefront/app/pages/admin/settings.vue` — grouped form with
  four `UCard` sections (Brand / Locale & Currency / Contact / Social
  links). Logo + favicon use T04's presign flow with
  `context: 'store-logo'` (existing enum value — no presign route
  change needed; favicon shares the `merchants/{id}/store-logo/…`
  prefix alongside logo). Social links render as key/value rows from
  the decoded `Record<string, string>` and serialize back to a JSON
  string on save. `USelect` items are built from
  `settings.supportedCurrencies` / `settings.supportedLocales` —
  empty-string sentinels are never passed to Reka's `SelectItem`
  (dropdowns only populate from non-empty values).
- `apps/storefront/app/layouts/admin.vue` restores the "Settings"
  sidebar link with the cog icon.

**Challenges encountered**:

- **Presign context mismatch.** The task brief said
  `context: 'store'` but the existing `ALLOWED_CONTEXTS` on
  `/api/admin/uploads/presign.post.ts` is
  `['product', 'category', 'store-logo']`. Used the existing
  `'store-logo'` context (same merchant-scoped prefix, just a
  different folder name) to avoid touching the presign route — that
  would be out-of-scope scope creep for T06. Favicon gets the same
  folder which is fine for MVP.
- **Reka SelectItem empty-value trap (carried over from T05).** Avoided
  by filtering out any falsy entries from `supportedCurrencies` /
  `supportedLocales` before mapping to `{ label, value }` — guarantees
  no empty-string `value` ever reaches a `SelectItem`.
- **socialLinks asymmetry.** Platform returns a `Record<string, string>`
  on GET; `UpdateStoreInput.socialLinks` is a JSON string on PATCH.
  Hydrated to form rows on load, serialized back on save (empty rows
  are dropped, an all-empty list is sent as `"{}"` so the backend can
  clear).
- **`useStoreInfo` caching on storefront.** The storefront's
  `useStoreInfo()` composable in `@commercejs/nuxt` uses
  `key: 'commerce:store'`, so a header/title change won't show until
  the storefront cache invalidates (navigation or hard reload). Added
  as a copy note on the form header rather than a programmatic
  invalidation (the dashboard has no cross-app reach into the
  storefront's Nuxt payload cache).
