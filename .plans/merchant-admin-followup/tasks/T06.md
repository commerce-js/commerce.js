# T06: Store Settings

---

**Status**: 🟡 **Planned**
**Effort**: Small
**Blocked By**: None — `admin.getStoreSettings()` / `updateStoreSettings()` already exist on `AdminAPI`.

## Goal

A logged-in merchant can edit their own store settings — display name (EN/AR),
description, logo URL, favicon, currency, locale, timezone, contact email &
phone, physical address, and social links — from `/admin/settings`. Changes
persist to the merchant's Neon branch and are immediately reflected in the
storefront header + footer (via `useStoreInfo` on `apps/storefront`).

## Context

The platform already exposes everything needed:

- `admin.getStoreSettings(): Promise<StoreSettings>` returning a rich
  payload (name, nameAr, description, descriptionAr, logo, favicon,
  currency, locale, timezone, supportedCurrencies, supportedLocales,
  contactEmail, contactPhone, address, socialLinks).
- `admin.updateStoreSettings(input: UpdateStoreInput): Promise<StoreSettings>`
  accepting a partial payload.

T06 is purely HTTP wrappers + one Vue page. Same shape as T05's read/write
routes. No platform change required.

## Requirements

### 1. API routes under `apps/dashboard/server/api/admin/settings`

- `settings.get.ts` — `admin.getStoreSettings()`.
- `settings.patch.ts` — body parsed with `updateStoreSettingsSchema` →
  `admin.updateStoreSettings(body)`.

Both gated by `requireMerchantSession`.

### 2. Zod schema in `admin-schemas.ts`

`updateStoreSettingsSchema` mirrors `UpdateStoreInput`:

```ts
export const updateStoreSettingsSchema = z.object({
  name: z.string().min(1).optional(),
  nameAr: z.string().optional(),
  description: z.string().optional(),
  descriptionAr: z.string().optional(),
  logo: z.string().url().optional().or(z.literal('')),
  favicon: z.string().url().optional().or(z.literal('')),
  currency: z.string().length(3).optional(),
  locale: z.string().optional(),
  timezone: z.string().optional(),
  contactEmail: z.string().email().optional().or(z.literal('')),
  contactPhone: z.string().optional(),
  address: z.string().optional(),
  socialLinks: z.string().optional(), // JSON string of key-value map
})
```

Follow the `parseOrThrow` pattern.

### 3. Settings page (`/admin/settings.vue`)

Tabbed or single-column form. Groups:

- **Brand** — name, nameAr, description, descriptionAr, logo, favicon (logo + favicon can reuse T04's presigned upload flow)
- **Locale** — currency dropdown (from `supportedCurrencies`), locale dropdown (from `supportedLocales`), timezone text
- **Contact** — email, phone, address (textarea)
- **Social** — repeating key/value rows (facebook, instagram, tiktok, x, whatsapp…) serialized as a JSON string

Save button persists via `PATCH /api/admin/settings`. Success toast. Error toast surfaces the Zod message.

### 4. Sidebar link

Restore the "Settings" entry in `apps/storefront/app/layouts/admin.vue`
(removed in `0804c3b`).

## Implementation Notes

- `socialLinks` comes back from the platform as a `Record<string, string>`
  but the `UpdateStoreInput` sends it as a serialized JSON string — mirror
  that asymmetry in the form (stringify on save, parse on load).
- Currency / locale changes don't retroactively convert product prices.
  Document that caveat in the page help text (or as a small warning
  modal) so merchants aren't surprised.
- Logo/favicon upload reuses `/api/admin/uploads/presign.post.ts` with
  `context: 'store'`, yielding `merchants/${id}/store/${uuid}/${filename}`.
