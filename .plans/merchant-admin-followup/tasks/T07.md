# T07: Customers (list + detail, read-first)

---

**Status**: 🟡 **Planned**
**Effort**: Small
**Blocked By**: None — `admin.listCustomers` / `getCustomer` / `deleteCustomer` already exist.

## Goal

A logged-in merchant can view their customers — paginated list with search,
and a detail page showing the customer's addresses and order history. Plus
a destructive "delete" action (GDPR / privacy ask). No editing of customer
data — that's a customer-scoped action (they edit their own profile from
the storefront).

## Context

Platform exposes:

- `admin.listCustomers(params?: AdminListParams): Promise<PaginatedResult<Customer>>`
- `admin.getCustomer(id: string): Promise<Customer>`
- `admin.deleteCustomer(id: string): Promise<void>`
- `admin.listOrders({ customerId })` already filters by customer (T05).

T07 wraps all four into /api/admin/customers/* + `/admin/customers/{index,[id]}.vue`.
Same shape as T05.

## Requirements

### 1. API routes under `apps/dashboard/server/api/admin/customers`

- `index.get.ts` — `?page=&perPage=&search=` → `admin.listCustomers(params)`.
- `[id].get.ts` — `admin.getCustomer(id)`.
- `[id].delete.ts` — `admin.deleteCustomer(id)`.

All gated by `requireMerchantSession`.

### 2. Zod schema

`listCustomersQuerySchema` mirrors the products list schema shape (page,
perPage, search).

### 3. List page (`/admin/customers/index.vue`)

- Search input (300 ms debounced) for email or name.
- `UTable`: email, name (firstName + lastName), phone, order count (if
  `admin.listCustomers` returns it; otherwise omit), createdAt, View
  action.
- Pagination via `UPagination`.
- URL query sync'd (same pattern as T03 products + T05 orders).

### 4. Detail page (`/admin/customers/[id].vue`)

Panels:

- **Profile** — email, phone, firstName, lastName, createdAt.
- **Addresses** — list from `customer.addresses` (Customer type has
  `addresses: Address[]`), render first+last name / street / city /
  country. Default address highlighted.
- **Orders** — reuse `GET /api/admin/orders?customerId=:id` + render the
  same list table component used in T05 (but simplified: order#, date,
  total, status). Click → existing `/admin/orders/:id`.
- **Danger zone** — "Delete customer" button with confirmation modal. On
  delete, redirect to the list.

### 5. Sidebar link

Restore "Customers" entry in `apps/storefront/app/layouts/admin.vue`
(removed in `0804c3b`).

## Implementation Notes

- **Read-first**: no edit from the admin side. Customer profile edits stay
  on the buyer-facing storefront. Surface that in a muted helper line so
  merchants don't ask.
- **Delete semantics**: `admin.deleteCustomer` — confirm whether the
  platform hard-deletes or soft-deletes before wiring the confirm modal
  copy. Current read of `packages/platform/src/admin/customers.ts`
  suggests hard delete; update the modal text accordingly.
- **Arabic names**: set `dir="auto"` on customer name cells for mixed
  RTL/LTR rendering (same pattern as T05 orders).
