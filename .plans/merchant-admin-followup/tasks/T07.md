# T07: Customers (list + detail, read-first)

---

**Status**: ✅ **Completed** (2026-04-19)
**Effort**: Small
**Blocked By**: None — `admin.listCustomers` / `getCustomer` / `deleteCustomer` already exist.

## Goal

A logged-in merchant can view their customers — paginated list with search,
and a detail page showing the customer's addresses and order history. Plus
a destructive "delete" action (GDPR / privacy ask). No editing of customer
data — that's a customer-scoped action (they edit their own profile from
the storefront).

## Context

Platform exposes:

- `admin.listCustomers(params?: AdminListParams): Promise<PaginatedResult<Customer>>`
- `admin.getCustomer(id: string): Promise<Customer>`
- `admin.deleteCustomer(id: string): Promise<void>`
- `admin.listOrders({ customerId })` already filters by customer (T05).

T07 wraps all four into /api/admin/customers/* + `/admin/customers/{index,[id]}.vue`.
Same shape as T05.

## Requirements

### 1. API routes under `apps/dashboard/server/api/admin/customers`

- `index.get.ts` — `?page=&perPage=&search=` → `admin.listCustomers(params)`.
- `[id].get.ts` — `admin.getCustomer(id)`.
- `[id].delete.ts` — `admin.deleteCustomer(id)`.

All gated by `requireMerchantSession`.

### 2. Zod schema

`listCustomersQuerySchema` mirrors the products list schema shape (page,
perPage, search).

### 3. List page (`/admin/customers/index.vue`)

- Search input (300 ms debounced) for email or name.
- `UTable`: email, name (firstName + lastName), phone, order count (if
  `admin.listCustomers` returns it; otherwise omit), createdAt, View
  action.
- Pagination via `UPagination`.
- URL query sync'd (same pattern as T03 products + T05 orders).

### 4. Detail page (`/admin/customers/[id].vue`)

Panels:

- **Profile** — email, phone, firstName, lastName, createdAt.
- **Addresses** — list from `customer.addresses` (Customer type has
  `addresses: Address[]`), render first+last name / street / city /
  country. Default address highlighted.
- **Orders** — reuse `GET /api/admin/orders?customerId=:id` + render the
  same list table component used in T05 (but simplified: order#, date,
  total, status). Click → existing `/admin/orders/:id`.
- **Danger zone** — "Delete customer" button with confirmation modal. On
  delete, redirect to the list.

### 5. Sidebar link

Restore "Customers" entry in `apps/storefront/app/layouts/admin.vue`
(removed in `0804c3b`).

## Implementation Notes

- **Read-first**: no edit from the admin side. Customer profile edits stay
  on the buyer-facing storefront. Surface that in a muted helper line so
  merchants don't ask.
- **Delete semantics**: `admin.deleteCustomer` — confirm whether the
  platform hard-deletes or soft-deletes before wiring the confirm modal
  copy. Current read of `packages/platform/src/admin/customers.ts`
  suggests hard delete; update the modal text accordingly.
- **Arabic names**: set `dir="auto"` on customer name cells for mixed
  RTL/LTR rendering (same pattern as T05 orders).

## Execution Summary

**Completed**: 2026-04-19

**What was implemented**:

- `listCustomersQuerySchema` added to `apps/dashboard/server/utils/admin-schemas.ts`
  (page/perPage/search/sortField/sortDirection — identical shape to
  `listProductsQuerySchema` minus `status`).
- Three dashboard routes under `apps/dashboard/server/api/admin/customers/`:
  - `index.get.ts` → `admin.listCustomers({ page, perPage, search, sort })`.
  - `[id].get.ts` → `admin.getCustomer(id)`, wraps thrown not-found as 404.
  - `[id].delete.ts` → `admin.deleteCustomer(id)`, returns 204 on success.
    Maps a `/not found/` platform error to 404; everything else surfaces as
    400 with the platform's message (so FK-blocked deletes on customers
    with orders show a readable reason in the toast).
- Two storefront pages under `apps/storefront/app/pages/admin/customers/`:
  - `index.vue` — `UTable` of email, name (firstName + lastName), phone,
    joined date. Debounced search (300 ms), URL query sync (`?q=&page=`),
    `UPagination` when `total > perPage`. Same shell as T05 orders list.
  - `[id].vue` — four-panel detail page:
    - **Profile** — email / firstName / lastName / phone / joined / updated.
    - **Addresses** — iterates `customer.addresses`, highlights the one
      matching `defaultAddressId` (or `isDefault`) with a "Default" badge.
      Address lines render with `dir="auto"` for mixed RTL/LTR names.
    - **Orders** — second `useFetch` to `/api/admin/orders?customerId=:id`
      (perPage=50), renders `orderNumber` (linked to existing
      `/admin/orders/:id`), date, total, status badge. Falls back to
      "This customer hasn't placed any orders yet."
    - **Danger zone** — red-bordered card with a "Delete customer"
      button. Confirm modal quotes the email, warns about FK-block on
      orders, hard-deletes via `DELETE /api/admin/customers/:id`, and
      redirects to the list on success.
  - Muted helper line below the header notes the page is read-only
    (customer profile edits stay on the buyer-facing storefront).
- Sidebar "Customers" entry restored in
  `apps/storefront/app/layouts/admin.vue` between Orders and Settings.

**Challenges encountered**:

- Pre-existing `Cannot find module 'h3'` typecheck errors surface on every
  admin route file (including T07's three new routes) — same condition on
  the already-shipped orders / products routes. Build is green and routes
  bundle correctly into `.output/server/chunks/.../api/admin/customers/*`,
  so this is a dashboard-wide typecheck noise, not a T07 regression.
- Addresses panel initially hit a TS strictness issue because `Address` is
  imported from `@commercejs/types` but used only in the script section —
  resolved by importing the type and typing `addressLines(addr: Address)`
  directly (no `any`). Kept in sync with the order detail page's pattern.
- `admin.deleteCustomer` on the platform currently throws `Error` with a
  `"Customer not found: X"` message for 404s rather than a typed error —
  regex-matched `/not found/i` to translate to a 404 status code. Brittle
  if the platform ever rewords the message; worth a follow-up typed-error
  pass on `admin.*` if this pattern spreads.
