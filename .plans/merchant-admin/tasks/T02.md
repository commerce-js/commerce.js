# T02: Admin Shell in apps/storefront

---

**Status**: ✅ **Completed** (2026-04-17)
**Effort**: Medium
**Blocked By**: T01 (session cookie + auth API must exist)

## Goal

A logged-in merchant can navigate `{sub}.commercejs.cloud/admin` and see a working shell:
left-nav (Dashboard / Products / Orders / Customers / Settings), authenticated header (store name
+ sign-out), and an `/admin/index` dashboard page populated with real stats from
`getDashboardStats()`. Unauthenticated visitors to any `/admin/**` path redirect to
`/admin/login`.

## Context

`apps/storefront` is a Nuxt app that runs on port 3001, proxied to from the dashboard for merchant-host traffic. It already imports `@nuxt/ui` v4 and `@commercejs/ui`. Adding `/admin/**`
pages reuses the existing Nuxt build, layout machinery, and tenant context. Admin pages will be
code-split out of the buyer bundle by Nuxt's router — merchants never download storefront code,
buyers never download admin code.

## Requirements

### 1. Login page (`apps/storefront/app/pages/admin/login.vue`)

Simple centered form: email, password, submit. Uses the default storefront layout? Probably
**no layout** (`definePageMeta({ layout: false })`) so the shop's nav/footer don't appear. On
submit, calls `$fetch('/api/admin/auth/login')`, on success navigates to `/admin` (or the
`?redirect` query param if present).

### 2. Admin layout (`apps/storefront/app/layouts/admin.vue`)

- Left nav: Dashboard (`/admin`), Products (`/admin/products`), Orders (`/admin/orders`), Customers (`/admin/customers`), Settings (`/admin/settings`). Active-route highlighting via `useRoute`.
- Header: store name (from `useStoreInfo()` — already wired in T03 storefront-eaas), current user email, sign-out button.
- Main content slot.
- RTL-aware (storefront is already locale-aware — `<html dir>` set from `useStoreInfo`).

Pages set `definePageMeta({ layout: 'admin' })`.

### 3. Client-side auth guard (`apps/storefront/app/middleware/admin-auth.global.ts` OR route-scoped)

Option A — global middleware that checks path starts with `/admin` and is not `/admin/login`:

```ts
export default defineNuxtRouteMiddleware(async (to) => {
  if (!to.path.startsWith('/admin') || to.path === '/admin/login') return
  const { data } = await useFetch('/api/admin/auth/session', { credentials: 'include' })
  if (!data.value) return navigateTo(`/admin/login?redirect=${encodeURIComponent(to.fullPath)}`)
})
```

Option B — named middleware applied per-page via `definePageMeta({ middleware: 'admin-auth' })`.

**Decide during implementation** — Option B is more explicit and keeps the buyer flow isolated
from admin-auth code. Option A is one fewer thing to remember per page.

### 4. Dashboard page (`apps/storefront/app/pages/admin/index.vue`)

Calls `$fetch('/api/admin/stats')` (new route — thin wrapper over `event.context.admin.getDashboardStats()`). Renders:

- Top cards: Total Products / Active Products / Total Orders / Total Revenue / Total Customers
- Orders-by-status bar or donut
- Recent orders table (5 rows)

Use `@nuxt/ui` v4 `UCard`, `UTable`, `UChip`. Keep it dumb — just data display. No filtering,
no drill-downs yet.

### 5. Stats API route

`apps/dashboard/server/api/admin/stats.get.ts`:

```ts
export default defineEventHandler(async (event) => {
  await requireMerchantSession(event)
  return event.context.admin.getDashboardStats()
})
```

### 6. Sign-out flow

Header button calls `$fetch('/api/admin/auth/logout', { method: 'POST' })` then
`navigateTo('/admin/login')`.

## Implementation Notes

- **Code splitting**: Nuxt splits each page into its own chunk. Admin pages won't ship to buyers unless they navigate into `/admin`. No extra config needed.
- **SSR vs CSR for admin**: admin pages can be CSR-only via `definePageMeta({ ssr: false })` if SSR causes hydration churn with the session-fetch. Start with SSR — Nuxt hydrates session-gated pages fine when the cookie is forwarded.
- **`useMerchantSession()` composable**: keep it thin. `useFetch('/api/admin/auth/session')` with `key: 'merchant-session'` so it's deduped per SSR pass.
- **Sign-out after session expiry**: if `/api/admin/auth/session` returns 401 mid-session (e.g. cookie expired), the middleware redirects to login on next navigation. No in-place expiry banner for v1.
- **RTL**: Arabic merchants see a RTL layout automatically via `<html dir>`. Nuxt UI v4 handles RTL natively, but spot-check the nav on `smoke` (locale `ar-SA`).

## Execution Summary

**Completed**: 2026-04-17

**What was implemented**:

- `apps/storefront/app/composables/useMerchantSession.ts` — thin composable
  that wraps `/api/admin/auth/{session,logout}`. Uses `useState` keyed
  `merchant-session` so the layout, middleware, and pages share one fetched
  identity per navigation. Exposes `user` ref, `fetchSession()`, `logout()`,
  and `clear()`. `credentials: 'include'` on both calls because the cookie
  is first-party but explicit is safer for cross-subdomain strictness in
  some browsers.
- `apps/storefront/app/middleware/admin.ts` — named route middleware
  applied per-page via `definePageMeta({ middleware: 'admin' })`. Returns
  immediately on the server pass (see SSR note below); on the client, it
  calls `fetchSession()` if no user is cached, and redirects to
  `/admin/login?redirect=<original path>` when no session exists.
- `apps/storefront/app/layouts/admin.vue` — left-nav shell. Sidebar has
  Dashboard / Products / Orders / Customers / Settings with active-route
  highlighting based on `useRoute().path`. Header shows the store name
  (from `useStoreInfo`), the signed-in user's email, and a Sign-out
  button that calls `logout()` then `navigateTo('/admin/login')`.
- `apps/storefront/app/pages/admin/login.vue` — centered `UCard` with
  `UInput` email + password fields, `UAlert` for the generic 401 error,
  and `UButton` submit. `definePageMeta({ layout: false })` so the shop's
  nav/footer aren't visible. On successful login, warms the shared
  session state via `fetchSession()` then navigates to `?redirect=` (if
  starts with `/admin`) or `/admin`.
- `apps/storefront/app/pages/admin/index.vue` — dashboard landing page.
  5 stat cards (Total products / Active products / Orders / Revenue /
  Customers), an orders-by-status list with colored `UBadge`s, and a
  recent-orders `UTable` (order number, status, total, placed-at). All
  data from `GET /api/admin/stats` via `useFetch` keyed
  `admin-dashboard-stats`. Uses `usePrice().formatPrice()` with the
  store's default-locale currency.
- `apps/storefront/app/pages/admin/products.vue` — "Coming in T03"
  placeholder that sets `layout: admin` so direct visits render inside
  the shell. Required by acceptance criterion #5.
- `apps/dashboard/server/api/admin/stats.get.ts` — thin wrapper around
  `event.context.admin.getDashboardStats()` behind `requireMerchantSession`.
  Tenant middleware handles merchant resolution + DB binding upstream, so
  the handler is three lines of business logic.

**Architecture decisions**:

- **Admin pages are CSR-only (`ssr: false`)**. The storefront Nitro
  (`:3001`) has no route for `/api/admin/*` — only `/api/storefront/*` is
  proxied by `@commercejs/nuxt`'s remote-mode handler. SSR'd calls to
  `/api/admin/stats` or `/api/admin/auth/session` would 404 locally.
  Rather than add a second storefront-side proxy for admin traffic, admin
  pages render a shell and then fetch on the client, where browser-origin
  `/api/admin/*` requests go to the Fly edge → dashboard directly (the
  existing dashboard-side `00.storefront-proxy.ts` rule keeps `/api/*` on
  `:3000`). Login page itself does SSR fine because it makes no fetches
  at render time.
- **Named middleware, not global**. Keeping `admin.ts` as a named route
  middleware (opted into per-page via `definePageMeta`) means buyer-facing
  pages never pull in the session-fetch code. Global admin-auth
  middleware would have added one `/api/admin/auth/session` call to every
  storefront page load.
- **Nav links for un-built pages stay in the sidebar**. Orders / Customers
  / Settings are part of the shell even though T03/T05+ land the pages.
  Clicking them before those tasks ship produces a Nuxt 404 page; this is
  expected and matches the single-commit rhythm — we don't stub pages
  that don't exist yet. Products is the exception because acceptance
  test #5 requires a placeholder visible inside the shell.

**Challenges encountered**:

- Initial draft imported `usePrice` explicitly and pulled `format` from
  the destructure; the real composable exports `formatPrice`. Caught on
  first build. Fixed by destructuring the correct name and dropping the
  explicit import (Nuxt auto-imports composables in `app/composables/`).
- Considered adding a storefront-side `/api/admin/**` catch-all proxy to
  enable SSR for admin pages, but dropped it — admin UIs have no SEO need,
  `ssr: false` is idiomatic for auth-gated dashboards, and a second proxy
  would mirror work the dashboard already does for free on the edge.
