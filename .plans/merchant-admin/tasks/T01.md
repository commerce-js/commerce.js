# T01: Merchant Auth Foundation

---

**Status**: 🟡 **Planned**
**Effort**: Medium
**Blocked By**: None — this is the entry point.

## Goal

Merchants can authenticate against their Neon branch's `admin_users` table via
`POST /api/admin/auth/login`, receive a `cjs-merchant-session` cookie scoped to their subdomain,
and have that session recognised by a new merchant-auth guard protecting `/api/admin/*`.
First-login bootstrap seeds the initial `admin_users` row from `Merchant.email` +
`Merchant.passwordHash` on the control DB.

## Context

Everything in this plan is session-gated. Without T01, admin pages have nobody to authenticate
and admin API routes have no way to distinguish legitimate staff from anonymous traffic. The
underlying auth domain (`createAdminAuthDomain()` in `packages/platform/src/admin/auth.ts`)
already implements login / CRUD / password-change / `seedInitialAdmin` — T01 is HTTP wrappers,
session wiring, and the control-DB fallback for first login.

## Requirements

### 1. Session utility (`apps/dashboard/server/utils/merchant-session.ts`)

Model after `utils/session.ts` (the platform-operator equivalent). Key shape:

```ts
export interface MerchantSession {
  userId: string       // admin_users.id on the merchant's branch
  merchantId: string   // must match event.context.merchant.id on every request
  email: string
  name: string | null
  role: 'owner' | 'admin' | 'editor'
}

const COOKIE_NAME = 'cjs-merchant-session'
const MAX_AGE_SECONDS = 60 * 60 * 24 * 7   // 7 days, matches dashboard session
```

Sealed h3 cookie, keyed by `NUXT_SESSION_PASSWORD` (same secret as dashboard session — different
cookie name + host scope prevents collision). `sameSite: 'lax'`, `secure: !dev`, `httpOnly: true`.

**Key consideration**: the cookie MUST be host-scoped (no `domain` attribute), so that
`smoke.commercejs.cloud`'s session doesn't get sent to `other.commercejs.cloud`.

### 2. Auth routes under `apps/dashboard/server/api/admin/auth/`

- `login.post.ts` — body `{ email, password }`. Calls `event.context.admin.auth.login()`. On
  "Invalid email or password" AND empty `admin_users`, attempts control-DB bootstrap (see
  requirement 4). Returns `{ id, email, name, role }`.
- `logout.post.ts` — clears the merchant session cookie.
- `session.get.ts` — returns the current session's user, or 401 if none.
- `register.post.ts` — **TBD — might be deferred to staff-invite flow.** If included,

### 4. First-login bootstrap from control DB

In `login.post.ts`, when `admin.auth.login()` throws and `admin_users.count === 0`:

```ts
const merchant = event.context.merchant   // populated by tenant middleware
if (!merchant.passwordHash) throw GENERIC_401

const valid = await compare(password, merchant.passwordHash)
if (!valid || merchant.email.toLowerCase() !== email.toLowerCase()) throw GENERIC_401

// Seed the first admin_users row on the branch
await event.context.admin.auth.createAdmin({
  email: merchant.email,
  password,                // plaintext — createAdmin hashes with bcrypt
  name: merchant.name,
  role: 'owner',
})

// Retry login — should now succeed
const user = await event.context.admin.auth.login(email, password)
```

Generic 401 for all failure paths — never leak "wrong password" vs "wrong email" vs "no such
merchant". Match `apps/dashboard/server/api/auth/login.post.ts` error hygiene.

### 5. Merchant-auth guard

A small utility (not a middleware — middlewares run for all routes and we want per-handler
opt-in) like:

```ts
// apps/dashboard/server/utils/merchant-auth.ts
export async function requireMerchantSession(event: H3Event): Promise<MerchantSession> {
  const session = await getMerchantSession(event)
  if (!session) throw createError({ statusCode: 401, message: 'Not authenticated' })
  if (session.merchantId !== event.context.merchant.id) {
    // Cross-tenant session replay attempt
    throw createError({ statusCode: 403, message: 'Session / tenant mismatch' })
  }
  return session
}
```

Called as the first line of every `/api/admin/*` handler (except the auth routes themselves).

## Implementation Notes

- **Control-DB `Merchant.passwordHash` nullable**: the schema has `passwordHash String?` — bootstrap must handle the null case (merchants provisioned without a password set get a clean 401, not a crash).
- **Name field**: `Merchant.name` is `String` not nullable. Platform's `admin_users.name` is nullable. Bootstrap passes `merchant.name` through — no null handling needed.
- **Role mapping**: `AdminUser.role` is a free-form string with `'admin'` default. Platform's `createAdmin` accepts `'owner' | 'admin' | 'editor'`. Bootstrap uses `'owner'`.
- **Fly secret sanity**: `NUXT_SESSION_PASSWORD` must be ≥32 chars in prod (already set). The merchant session reuses this — no new secret needed.
