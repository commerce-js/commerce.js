# T04: Image Upload (Presigned S3)

---

**Status**: ✅ **Completed** (2026-04-17)
**Effort**: Medium
**Blocked By**: T03 (product form needs the image field wired)

## Goal

Merchants can attach product images to the product form. Images are uploaded directly from the
browser to S3 (via presigned PUT URL) under a per-merchant key prefix, and the resulting public
URL is stored on the product record. No images traverse our Fly app — the server only
issues short-lived presigned URLs.

## Context

`@commercejs/storage-s3` (`packages/storage-s3/src/s3-storage-provider.ts`) wraps S3 REST via
`aws4fetch` and exposes `upload`, `getPresignedUrl`, and `delete`. It works with any
S3-compatible provider (AWS, R2, DigitalOcean Spaces, MinIO). For v1 we pick one bucket and
partition by prefix; per-merchant buckets are an enterprise-tier follow-up.

The presigned-URL flow keeps the upload off our server (no large multipart bodies, no sharp,
no memory pressure). Fly `commercejs-cloud` stays lean.

## Requirements

### 1. Presign endpoint (`apps/dashboard/server/api/admin/uploads/presign.post.ts`)

Request:
```ts
{
  filename: string      // original name
  mimeType: string      // MIME type
  size: number          // bytes, for server-side limit enforcement
  context?: 'product' | 'category' | 'store-logo'  // optional, affects key layout
}
```

Response:
```ts
{
  uploadUrl: string     // presigned PUT URL
  publicUrl: string     // final URL after upload (CDN or S3 direct)
  key: string           // bucket key (for debugging / delete later)
  expiresIn: number     // seconds
}
```

Handler logic:

1. `await requireMerchantSession(event)` — standard gate.
2. Validate mimeType against allow-list: `image/jpeg`, `image/png`, `image/webp`, `image/gif`.
3. Enforce max size (e.g. 10 MB) server-side — belt-and-braces, S3 can enforce via `Content-Length`.
4. Compute key: `merchants/${merchant.id}/${context ?? 'products'}/${crypto.randomUUID()}/${safeFilename}`. Safe-filename = lowercase + strip special chars.
5. Instantiate `new S3StorageProvider({ ...cfg, prefix: '' })` — prefix is in the key explicitly, NOT the config, so the config stays stateless across merchants.
6. `getPresignedUrl({ key, mimeType, method: 'PUT', expiresIn: 900 })`.
7. Compute `publicUrl` from `publicUrl` config (CDN) or direct bucket URL.
8. Return.

### 2. Fly secrets (gate: check with user before `fly secrets set`)

```
NUXT_S3_ENDPOINT         # e.g. https://s3.eu-central-1.amazonaws.com, OR R2 endpoint
NUXT_S3_REGION           # e.g. eu-central-1, 'auto' for R2
NUXT_S3_BUCKET           # single shared bucket name
NUXT_S3_ACCESS_KEY_ID
NUXT_S3_SECRET_ACCESS_KEY
NUXT_S3_PUBLIC_URL       # optional CDN base, e.g. https://cdn.commercejs.cloud
NUXT_S3_FORCE_PATH_STYLE # optional, needed for MinIO
```

Pick a provider BEFORE starting T04:

- **AWS S3** — mature, MENA-friendly region (me-central-1 Bahrain).
- **Cloudflare R2** — free egress, but we're moving AWAY from CF.
- **Bunny Storage** — cheap, CDN-bundled.

**Decision pending user input**. AWS in `me-central-1` is the lowest-risk default for the
MENA-first audience.

### 3. Runtime config

`apps/dashboard/nuxt.config.ts` — add an `s3` runtimeConfig block reading the env vars above.
Export a `getS3Config()` util that reads `useRuntimeConfig()` in server context.

### 4. Bucket setup

Once provider is chosen:

- Bucket name (e.g. `commercejs-cloud-assets`).
- CORS rules allowing PUT from `*.commercejs.cloud` (and any verified custom domain host).
- Lifecycle: none for v1 (don't auto-delete).
- Public-read on `merchants/**` so `publicUrl` is resolvable. (Alternative: signed GETs, but that complicates storefront rendering.)
- IAM user with scoped permissions: `PutObject`, `GetObject`, `DeleteObject` on `merchants/*`.

### 5. Product form integration (edits to T03 form)

- Add image drop-zone / file picker.
- For each selected file:
  1. `$fetch('/api/admin/uploads/presign', { method: 'POST', body: { filename, mimeType, size } })`.
  2. `fetch(uploadUrl, { method: 'PUT', body: file, headers: { 'Content-Type': mimeType } })`.
  3. On success, push `{ url: publicUrl, altText: '', sortOrder: i, isPrimary: i === 0 }` into the form's `images` array.
- Preview thumbnails for queued images; allow reorder + set-primary + delete-before-save.
- Primary-image radio: exactly one `isPrimary: true` enforced client-side.

### 6. Orphan handling

A failed save after successful uploads leaves orphans in S3. For v1, accept this — an eventual
weekly BullMQ sweep can reconcile (out of scope). Don't add cleanup logic to the submit path —
it creates races.

## Implementation Notes

- **Why presigned PUT, not server upload**: server upload requires the file to traverse Fly, which means memory pressure and bandwidth cost. Presigned PUT is one round-trip to our server, then a direct browser-to-S3 transfer — zero Fly bandwidth for the actual file.
- **MIME sniffing**: trust the client-provided MIME for presign — S3 enforces `Content-Type` via the signed header. A mismatch between client-advertised type and actual bytes is caught at storefront render time (broken image), not by us.
- **`publicUrl` computation**: if `NUXT_S3_PUBLIC_URL` is set, use `${publicUrl}/${key}`. Otherwise `${endpoint}/${bucket}/${key}` (virtual-hosted) or `${endpoint}/${bucket}/${key}` with `forcePathStyle`.
- **Deletion**: if a merchant deletes a product, its images stay in S3 for v1. Accept the cost.
- **Image optimization**: none at upload time. Serve via `@nuxt/image`'s existing IPX transform in the storefront — no new infra. Add Bunny/Cloudinary transform later if IPX's cost profile is wrong.

**Completed**: 2026-04-17

**What was implemented**:
- `POST /api/admin/uploads/presign` in `apps/dashboard/server/api/admin/uploads/`
  behind `requireMerchantSession`. Zod-validated body (`filename/mimeType/size/
  context?`). Mime allow-list (jpeg/png/webp/gif → 400). 10 MB cap (413). Key
  composed server-side as `merchants/${merchant.id}/${context ?? 'product'}/
  ${crypto.randomUUID()}/${safeFilename}` — `sanitizeFilename` strips path
  traversal, lowercases, and normalizes to `[a-z0-9-_]`. 900s presign expiry,
  `Content-Type` bound into the SigV4 signature.
- `apps/dashboard/server/utils/s3.ts` — `getS3Config()` reads Fly-native env
  vars (`AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_ENDPOINT_URL_S3`,
  `AWS_REGION`, `BUCKET_NAME`) directly via `process.env`, matching the
  `NEON_CONTROL_DB_URL` pattern in `server/utils/db.ts`. Throws a clear 500
  listing missing vars if unconfigured. `publicUrlForKey()` mirrors the
  provider's virtual-hosted URL math decoupled from the provider instance
  (used to return `publicUrl` in the presign response).
- `apps/dashboard/package.json` — added `@commercejs/storage-s3: workspace:*`.
- `AdminProductForm.vue` — Images card with drag-drop zone + file picker
  (`accept="image/jpeg,image/png,image/webp,image/gif"` + `multiple`), preview
  grid (2/3/4-col responsive), per-image alt-text, star-icon "Set primary"
  button, up/down reorder, trash delete, auto-primary on first upload.
  `uploadingCount` + `uploadError` reactive state for feedback. Initial images
  populated from `props.initial?.primaryImage + gallery` on edit.
- `useAdminProductForm.ts` — `toPayload()` now maps `form.images` into the
  `images[]` payload, re-indexes `sortOrder` on submit, falls back to index-0
  primary if none marked.
- `@commercejs/storage-s3` — **upstream bug fix**: `getPresignedUploadUrl` and
  `getPresignedDownloadUrl` were setting `X-Amz-Expires` on the URL AFTER
  calling aws4fetch's `sign()`, invalidating the signature (aws4fetch defaults
  `X-Amz-Expires=86400` internally when missing at sign time; overwriting it
  post-hoc meant the signature was computed against one expires value and the
  URL carried another). Fix: set `X-Amz-Expires` on the URL before signing.

**Infrastructure set up (via Fly CLI + ad-hoc node script):**
- `fly storage create --name commercejs-cloud-assets` — Tigris bucket provisioned;
  creds auto-injected on Fly app as `AWS_*` / `BUCKET_NAME` secrets.
- `fly storage update commercejs-cloud-assets --public` — bucket set to
  publicly readable. Tigris does not currently implement `PutBucketPolicy`
  (returns 501 `NotImplemented`), so prefix-scoped public-read
  (`merchants/**` only) is deferred to a provider-level capability. The
  bucket exclusively holds `merchants/${id}/...` content so "whole bucket
  public" is equivalent in practice.
- `PutBucketCors` applied via a small aws4fetch-based node script (run from
  inside `packages/storage-s3` so `aws4fetch` resolves; script deleted post-
  use). Final CORS rule: `AllowedOrigin: *`, `AllowedMethod: PUT/GET/HEAD`,
  `AllowedHeader: *`, `ExposeHeader: ETag`, `MaxAge: 3600`. Wildcard-subdomain
  origin (`https://*.commercejs.cloud`) caused Tigris to 403 the preflight
  — Tigris does not support subdomain-wildcards in CORS origins. `*` is
  safe here because writes require a presigned URL (signed by our IAM user
  scoped to our bucket) and reads are already bucket-public.
- **No** `NUXT_S3_*` secrets on Fly — app reads the native `AWS_*` names
  directly, avoiding a duplicate secret layer.
- `@commercejs/dashboard` + `@commercejs/storage-s3` workspace-linked.
