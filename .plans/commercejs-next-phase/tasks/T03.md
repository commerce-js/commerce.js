# T03: Client Plugin Update

---

**Status**: 🟡 **Planned**
**Effort**: Small
**Blocked By**: None

## Goal

Update the Nuxt client plugin so `$commerce` is available on the client side. Since we chose Option A (server-only tokens), the client plugin should provide a lightweight proxy adapter that calls the server API routes via `$fetch`.

## Context

Currently `plugin.ts` reads `$commerce` but never creates it. The composables use `useAdapter()` → `$commerce`. For SSR, the Nitro server plugin injects the real adapter. For client-side navigation (SPA mode), we need a proxy that routes calls to `/api/_commerce/*`.

## Requirements

### 1. Client Plugin Update

Since composables run during SSR (where the Nitro plugin provides the real adapter), the client plugin only needs to handle client-side navigation. Two sub-options:

**Sub-option A (Simpler)**: Mark the adapter as SSR-only. Composables using `useAsyncData`/`useState` already cache SSR data — client-side navigation reuses it.

**Sub-option B**: Create a fetch-based proxy adapter that implements `CommerceAdapter` and delegates to `/api/_commerce/*`.

For now, **Sub-option A** is sufficient — the composables use `useState` which persists across SSR → client hydration.

### 2. Plugin provides flag

Set `$commerce` to the adapter on server side. On client, it can be `undefined` (composables should handle this gracefully via `useAsyncData`).
