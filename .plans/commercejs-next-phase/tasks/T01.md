# T01: Token Refresh in SallaClient

---

**Status**: 🟢 **In Progress**
**Effort**: Medium
**Blocked By**: None

## Goal

Add automatic OAuth token refresh to `SallaClient` so that when a 401 is encountered, the client refreshes the token and retries the request transparently.

## Context

Salla OAuth tokens expire (typically 14 days). Currently, if a token expires, all API calls fail with UNAUTHORIZED. The token refresh should happen server-side only (Option A from the research). The Nitro server plugin passes refresh credentials to the adapter.

## Requirements

### 1. Extend `SallaConfig`

Add optional fields to `SallaConfig`:
```typescript
refreshToken?: string
clientId?: string
clientSecret?: string
```

### 2. Token Refresh Logic in `SallaClient`

- On 401 response, call Salla's `POST https://accounts.salla.sa/oauth2/token` with `grant_type=refresh_token`
- Update the internal `accessToken` with the new token
- Retry the failed request once
- If refresh fails, throw the original UNAUTHORIZED error
- Prevent concurrent refresh attempts (mutex/flag)

### 3. Update Nitro Server Plugin

The Nitro plugin (`commerce-adapter.ts`) already passes `refreshToken`, `clientId`, `clientSecret` from env vars — config shape just needs to match.

## Action Items

- [ ] Happy path: Token refresh succeeds, request retried and succeeds
