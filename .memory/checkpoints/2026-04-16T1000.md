## Known Carry-Overs

1. **Credit-card checkout flow** is broken — `/checkout/complete` redirects to
   `https://checkout.commercejs.cloud/pay/cart?id=...`, which 404s. The hosted-checkout
   app was on Cloudflare before the Fly migration, its DNS still CNAMEs to Fly's wildcard
   and is getting caught by `commercejs-cloud`'s catch-all (which doesn't have a
   `/pay/cart` route). **Fix path**: either deploy `apps/hosted-checkout` as a separate
   Fly app and move the DNS, or fold `/pay/*` routes into the existing
   `commercejs-cloud` deploy. Out of scope for this session; not blocked on seed work.

2. **Google Maps console warnings** — two deprecation notices from
   `apps/storefront/app/pages/checkout.vue:loadGoogleMaps()`:
   - Script tag missing `loading=async` (perf, not correctness)
   - `google.maps.Marker` is soft-deprecated in favor of `google.maps.marker.AdvancedMarkerElement`
   Spawned as a side-task (see `spawn_task` trail).

3. **`profiles.ts` latent type errors** — `Record<string, any> | null` in
   `createProfile`/`createProfilePaymentMethod` signatures doesn't satisfy Prisma 7.7's
   strict `NullableJsonNullValueInput` input type. Dormant today because platform
   doesn't declare `@prisma/client` as a dep (see `.memory/gotchas.md` entry). Would
   need `Prisma.DbNull` sentinel handling before that dep can be safely declared.

4. **Phase-2 composables still on `useAdapter()`** — `useReviews`, `useReturns`,
   `useWishlist`, `usePromotions`. Not wired for remote mode. Tracked in the plan.

5. **Merchant admin UI (Next-step B)** is the real gate for onboarding real merchants.
   Unchanged from previous checkpoint — recommended as the next major scope.

## Architecture Notes (New)

**`scripts/` as a workspace package.** Previously the repo had a `scripts/` directory
with only `start-web.sh` and no package.json. Running any TS script from root failed
module resolution for `@commercejs/*` workspace packages because the root wasn't a
consumer. Making `scripts/` its own private workspace lets it declare workspace deps
(`@commercejs/platform: workspace:*`) and a local tsx, so `pnpm exec tsx` from repo root
"just works" and future operational scripts have an obvious home.

**`public-hoist-pattern[]=@prisma/client` in `.npmrc`.** Prisma's generated client
(`packages/platform/dist/.../internal/class.js`) does a runtime `import` of
`@prisma/client/runtime/client` but the platform package doesn't declare it. Bundled
consumers resolve it at build time; unbundled Node (e.g. `tsx scripts/…`) can't. Root
hoisting puts `@prisma/client` where Node's upward walk from platform/dist can find it,
without forcing platform to declare the dep (which trips dormant Prisma-7.7 strict
type errors in `profiles.ts` — see gotchas).
