  equivalents)

- Requires `nitro.experimental.asyncContext: true` to enable `useEvent()`

## Architecture — `getDb()` resolution path

```
Consumer calls getDb()
       │
       ▼
  ┌────────────────────────────┐
  │ 1. registered event        │  ← preferred (concurrency-safe)
  │    resolver → event?.db    │     Requires framework plugin to
  └────────┬───────────────────┘     register resolver + middleware
           │ miss                     to set event.context.db
           ▼
  ┌────────────────────────────┐
  │ 2. tenantStore (ALS)       │  ← works with runWithDb(), brittle
  │    .getStore()             │     via bindDb in middleware
  └────────┬───────────────────┘
           │ miss
           ▼
  ┌────────────────────────────┐
  │ 3. module-level _db        │  ← single-tenant CLI / seed /
  │    (initPrisma singleton)  │     tests. Racy for multi-tenant.
  └────────┬───────────────────┘
           │ miss
           ▼
         throw
```

## Known Carry-Overs (documented for follow-up)

1. **Dashboard still uses the legacy `bindDb` + `initPrisma` path.** Works
   today because smoke is single-tenant, but races under concurrent
   multi-tenant traffic. Migrate to `event.context.db` + the platform
   event resolver next time the file is touched.
   Files: `apps/dashboard/server/middleware/tenant.ts`, new plugin at
   `apps/dashboard/server/plugins/platform-event-resolver.ts`, enable
   `experimental.asyncContext: true` in nuxt.config.

2. **Hosted-checkout eventually wants its own Fly app.** Reasons: PCI scope
   reduction (separate process space from storefront bundling third-party
   JS), independent scaling (card bursts vs browse traffic), failure
   isolation (storefront crash shouldn't kill checkout). Current
   co-supervised setup is fine for smoke / pre-prod. Move before real card
   volume. Path: new `fly.toml` + reuse Dockerfile, CNAME DNS.

3. **Per-merchant Tap secret keys.** `server/utils/tap.ts` still reads
   `TAP_SECRET_KEY` from env as a fallback. For real production, add a
   `payment_config` table (merchant DB or control DB) and read per-request.
   TODO marked inline.

4. **`server/utils/delivery.ts`** uses raw `neon(process.env.DATABASE_URL)`
   because there's no `Integration` model in the Prisma schema. TODO
   inline — should either be moved to Prisma (add the model) or read
   `event.context.merchant.database_url` for the right per-tenant URL.

5. **`server/utils/merchant-store.ts`** is an in-memory store for Tap
   credentials. Loses state on process restart. Fine for MVP.

6. **Webhook tenant resolution.** `/api/webhooks/tap-payment` and
   `/api/webhooks/tap-connect` don't carry a `merchant` param — needs a
   cart→merchant or charge-metadata lookup path. Not in today's scope.

7. **Google Maps deprecation warnings** — separate spawned task (from
   previous session), not touched today.
