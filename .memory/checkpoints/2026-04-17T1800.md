### Per-event Prisma binding (the scalable ALS fix)

`packages/platform/src/database/prisma/client.ts` grew a new `registerEventResolver()` export.
`@commercejs/platform`'s `getDb()` now tries resolution in this order:
1. Nitro `useEvent()` (from `nitropack/runtime`) → `event.context.db` if the resolver is
   registered — this is the scalable, per-request, concurrency-safe path.
2. `AsyncLocalStorage.getStore()` (legacy `bindDb()` path) — still supported for
   non-Nitro consumers (seed scripts, CLI).
3. Module-level `_db` set by `initPrisma()` — last-resort fallback.

The hosted-checkout uses approach (1): `server/plugins/platform-event-resolver.ts`
registers the resolver at Nitro boot, and `server/middleware/tenant.ts` sets
`event.context.db = getPrismaClient(merchant.database_url)` per request.

**Dashboard still on (2)+(3).** Works today only because `ensureAdapter()` → `createPlatformAdapter()` → `initPrisma()` sets `_db` as an accidental fallback. Race-prone
under concurrent different-merchant traffic but masked at smoke. Migrating dashboard's
tenant middleware to the per-event pattern is a pre-production task (see carry-overs).

## Carry-Overs

1. **Dashboard tenant middleware still on the `bindDb()` + `_db` fallback path.** Works
   today because `ensureAdapter()` calls `initPrisma()` which sets `_db`. Race-prone under
   concurrent different-merchant traffic. Fix: migrate to the per-event pattern
   (`registerEventResolver()` + `event.context.db`) that hosted-checkout now uses. **Gates
   production traffic** — not needed for MVP smoke.

2. **Dashboard needs per-event migration before T01 of merchant-admin lands production
   traffic.** Once `/api/admin/*` is unlocked (T01 removes it from SKIP_PREFIXES), every
   admin route uses the same middleware — so the concurrency race surfaces on admin calls
   too. Worth adding as a post-MVP task in `.plans/merchant-admin/plan.md` before shipping
   multi-merchant admin traffic.

3. **`NUXT_*` gotcha is sticky.** Three hits across two sessions. Before adding any new
   `runtimeConfig.*` key (public or server-side), the reflex check should be: "What's the
   matching Fly secret name?" Pre-deploy checklist item, or at least keep it near the top
   of `.memory/gotchas.md`.

4. **Google Maps deprecation warnings** — still spawned as a side-task from earlier.
   Not urgent.

5. **`profiles.ts` Prisma-7.7 NullableJson type errors** — dormant. Only surfaces if
   `@prisma/client` is ever declared on `@commercejs/platform`.
