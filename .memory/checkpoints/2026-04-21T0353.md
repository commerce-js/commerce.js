## Architectural decisions worth carrying forward

- **Worker handlers must live in a side-effect-free module.**
  Extracting `handleProvisionStore`, `handleSendEmail`,
  `handleDispatchWebhook` out of `worker.ts` into
  `server/utils/worker-handlers.ts` is the shape for every future
  handler — vitest can mock their deps without Redis connecting. The
  BullMQ Worker bootstrap in `worker.ts` only imports the handlers
  and wires the dispatch switch. Same pattern if T06 (trial-ending)
  adds a repeatable-job handler.
- **Dashboard vitest setup is minimal but real.** One
  `vitest.config.ts`, one `test` script — no per-package devDep
  since root `vitest` is resolvable from workspace nodes. T02+ tests
  should land in `apps/dashboard/__tests__/` or
  `apps/dashboard/server/emails/__tests__/` without further setup.
- **Template subjects belong to the template, not the job.**
  `SendEmailJob.subject` is optional; the worker falls back to the
  template's own `subject()` when the job doesn't supply one.
  Consistent wording across every send of a given template, fewer
  places to translate when Arabic lands.
- **Token format is 32 random bytes → base64url → sha256 hex at
  rest.** Matches GitHub/Shopify/Slack invite patterns. Raw token
  exists only in the email URL + the accept request body. Never
  logged. Race-safe consumption via `WHERE used_at IS NULL`
  predicate in the UPDATE.
- **admin_users.password_hash is now nullable on the merchant DB.**
  Idempotent `ALTER COLUMN DROP NOT NULL` in both `migratePrisma`
  and `migrateDrizzle`; Prisma model is `String?`. The `invited`
  state is the only case that writes null, and `admin.auth.login`
  rejects these rows before `bcrypt.compare` would crash. Mechanical
  decision, but a load-bearing one — documenting so future password
  reset / bot-lockout work doesn't re-derive it.
- **`inviteUrl` is built from the request host + protocol.** No
  hardcoded `commercejs.cloud` — a merchant on a verified custom
  domain gets an invite link at their own domain. `getRequestHost`
  + `getRequestProtocol` both honor the `X-Forwarded-*` headers the
  Fly edge supplies, so the path works behind the Fly proxy.
- **Dashboard `/api/admin/staff/index.post.ts` breaking-change
  pattern.** The platform's `createAdmin` return type switched from
  `AdminUserSafe` to `{admin, invite}`. Callers must destructure.
  Both in-tree callers (staff index.post.ts, auth login.post.ts
  bootstrap) updated alongside the platform change — don't commit
  platform API signature changes that would break the dashboard
  build in the intermediate state.
