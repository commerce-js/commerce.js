## Architecture Decisions This Session

- **`ActivityEvent` type stays in `@commercejs/platform/admin/types.ts`**,
  not `@commercejs/types`. Rationale: purely platform-admin concern, no
  cross-package consumer. Avoids a `types → core → platform` rebuild
  cascade on a type with no external users. T12's `StoreTheme` went the
  other way (cross-package consumer — `useStoreInfo` on storefront reads
  it); T13's scope is narrower, so local-to-platform is the right call.
- **Audit helper is fire-and-forget** by design. Blanket `try { } catch
  { }` in `apps/dashboard/server/utils/audit.ts` swallows every error
  from session read, platform call, or Prisma insert. Verified via (1)
  code inspection, (2) 9 unit tests including null-actorId + null-diff
  paths, (3) 5 live mutation→audit pairs on smoke all returning 200.
  Non-negotiable: audit writes MUST NEVER fail a business mutation.
- **Diff payload discipline**: only changed keys or specific context
  values (trackingNumber, role), never full entity snapshots. Keeps
  the table small and the diff searchable.
- **`actor_id` is NOT FK-cascaded to `admin_users.id`.** Intentional —
  deleting an admin must not delete audit rows. Past rows keep pointing
  at the orphan UUID; the UI relies on the snapshotted `actor_email`
  column for display. A second-pass UI polish (tag orphaned rows by
  cross-checking against live `listAdmins()`) is a v2 concern.
