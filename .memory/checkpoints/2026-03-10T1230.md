# Checkpoint: 2026-03-10T1230

## Summary
Resolved Cloudflare Pages CI deploy failure for `@commercejs/nuxt` module server routes. 16 versions tested (0.6.10–0.6.21) before finding the correct solution.

## Root Cause
`addServerHandler` (and `addTemplate` + `addServerHandler`) bypass Nitro's auto-import injection pipeline. Files registered this way — whether in `node_modules/` or `.nuxt/` — do NOT receive auto-imports for `defineCommerceHandler`, `defineEventHandler`, or any other function.

## Fix
Replaced ~90 lines of manual `registerApiRoutes`/`stripAllImports`/`addTemplate` machinery with:
```typescript
addServerScanDir(resolve('./runtime/server'))
```
Handler source files (74 files) stripped of all explicit imports — rely entirely on Nitro's auto-import system.

## Key Files Modified
- `packages/nuxt/src/module.ts` — replaced registerApiRoutes with addServerScanDir
- `packages/nuxt/src/runtime/server/api/**/*.ts` — stripped all import statements (74 files)

## Commits
- Multiple fix(nuxt) commits from 0.6.10 through 0.6.21
- Final working version: `@commercejs/nuxt@0.6.21`

## Validation
- CI run #22895748079 on `masterde/gggg`: **success** ✅
- CF Pages deployment: `✨ Deployment complete!`

## Gotchas Learned
- `addServerHandler` bypasses Nitro's auto-import pipeline — use `addServerScanDir` for modules shipping server routes
- `addTemplate` files in `.nuxt/` also don't receive auto-imports when registered via `addServerHandler`
- Rollup creates module identity conflicts when a function is both auto-imported AND explicitly imported (`defineCommerceHandler$1`)
- Package export import paths need `.js` extension for Rollup to find files
