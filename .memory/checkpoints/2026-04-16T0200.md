### Key architectural decisions made this session

1. **Co-supervised web process** (not Fly's `[processes]` split) — one machine runs dashboard + storefront side by side via `scripts/start-web.sh`. Rationale: localhost works, no `.internal` DNS plumbing, one health check covers both.
2. **Remote-mode detection keys off `apiRoutes: false`** in `nuxt.config.ts`, not the `NUXT_COMMERCE_REMOTE_API_BASE` env var. Rationale: env var isn't visible to `nuxt build` in Docker; config option is.
3. **AsyncLocalStorage for X-Forwarded-Host propagation** across Nuxt's in-process `$fetch` boundary. `event.context` doesn't survive; headers on `proxyRequest` see the inner (localhost) event. ALS is the only channel that carries the outer request's merchant host into the proxy handler. See `packages/nuxt/src/runtime/server/plugins/proxy-forwarded-host.ts`.
4. **Storefront assets at `/_storefront/`** instead of the default `/_nuxt/`. Dashboard and storefront both emit `_nuxt/` with differently-hashed files; shared-machine deploy has the dashboard's Nitro handler catching `/_nuxt/**` and 404ing storefront hashes. Changing `app.buildAssetsDir` decouples them. Extends naturally to `/_themes/<name>/` for phase-2 themes.
5. **Dropped page-level SWR on the storefront.** Nitro SWR keys by path only — no vary-by-host — which leaks one merchant's rendered HTML to every subdomain. Re-introducing SWR requires per-tenant cache keys.

## What's Blocking "Real Merchant Onboarding"

1. **Zero catalog on smoke tenant.** `GET /api/storefront/products` returns `[]`. Can't exercise add-to-cart in a browser.
2. **No merchant admin UI.** Merchants have no way to create products / manage orders. Platform-operator dashboard at `app.commercejs.cloud` is for CommerceJS staff, not merchants.
